Programme economics

Rules

Rule catalogue

Each rule runs in dbt at its own grain: a material, a material × plant row, a vendor, or a vendor × company code. DQ precision and recall ask whether the rule flagged the right records, checked against the generator's defect ledger. For the duplicate rules (M10, V07) they count surplus records per true entity, because which record survives is a survivorship choice. Pairwise matching accuracy is a separate metric, shown in the entity-resolution panel.

Pairwise accuracy

A golden record

Kestrel Flexibles is a fictional flexible-packaging converter. All records are synthetic, generated on real SAP table structures with defects injected on purpose so every rule and model can be scored against ground truth.
Pipeline: Python generator → Great Expectations landing gate → Splink entity resolution + survivorship → dbt (DuckDB) rules, scores, trend → Monte Carlo cost model
